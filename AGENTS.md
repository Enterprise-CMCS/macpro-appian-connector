- Do not add a frontend page, banner, or feature flag for credential-change downtime unless directed.

## Learned Workspace Facts

- Connector DB details live in AWS Secrets Manager, not SSM. Master and ephemeral deploys read `appian/default/dbInfo` because `appian/master/dbInfo` does not exist. Val reads `appian/val/dbInfo` and production reads `appian/production/dbInfo`. JSON fields are `ip` (host), `port`, `db` (Oracle SID in the thin JDBC URL), `user` (login), `schema` (table qualifier), and `password`. Do not commit concrete `user`, `schema`, `db`, password, host, account ID, ARN, or EventBridge physical name values. The MACPro application login is separate from the connector login. The master/dev Oracle database is in a separate MACPro account, so database networking changes use that account rather than the `bigmac-dev` profile. Leave the val account’s separate `appian/default/dbInfo` unchanged.
- Database username and password changes are manual; do not reintroduce an automatic password updater. Full steps: https://confluenceent.cms.gov/pages/viewpage.action?pageId=1504366491. Do not commit account IDs, secret values, ARNs, or EventBridge physical names. `configureConnectors` reads `legacydbPassword` from its Lambda environment (set at deploy), not Secrets Manager at runtime; it reads connector status once after the config PUT, throws on auth/lock traces without restarting, does not poll, and does not change the dbInfo secret.
- The master stage is the dev environment; ephemeral branches deploy there. A push to `master` auto-opens a release PR to `val`, and a push to `val` auto-opens one to `production`. AWS CLI profiles: `bigmac-dev` (master), `bigmac-val` (val), `bigmac-prod` (production). Key Lambdas: `appian-connector-{stage}-configureConnectors`, `-testConnectors`, and (val/production only) `-jiraNotifier`.
- `testConnectors` runs every minute from an EventBridge rule whose state comes from `healthCheckSchedule` in `infra/lib/environment-config.ts`. Master is `ENABLED`; val is `ENABLED`; production stays `DISABLED` until Task 18 of `docs/appian-connector-stability-plan.md` (restarts once locked the Oracle user). Disable the stage’s EventBridge rule to stop runs, and keep `healthCheckSchedule` in sync. It emits `{connectorName}_failures`, `_task_failures`, `_restart_capped`, `health_check_heartbeat` (every run), and `_restarts` before a restart (skip restart if that publish fails). It restarts non-RUNNING connectors except on Oracle auth/lock traces, at most `maxRestartsPerHour` (default 3) times per hour, and does not restart if it cannot read the restart count. Config sets `connection.attempts` to 1; it cannot push new credentials.
- From `tasks[].trace`: `ORA-01017`, `ORA-28000`, or `account locked` emit `{connectorName}_oracle_auth_failures` 1 and `_oracle_errors` 1 and skip restart; any other `ORA-` emits auth 0 and oracle 1 and keeps the restart rule; no Oracle trace emits 0 and 0.
- Connection alarms in `infra/lib/connector-alarms.ts` cover every name in `src/services/connector/libs/connector-names.json`: `appian-connector-{stage}-conn-{short}-connector-down`, `-task-down` (Max >= 1, 3 of 5), `-oracle-auth` (Sum >= 1, 1 of 1), `-restart-capped`, plus `-conn-health-check-missing` (only when the schedule is enabled) and `-conn-health-check-errors`. `{short}` drops the `source.jdbc.` prefix. All notify `Alerts-appian-alerts-{stage}` (email subscriptions are manual and must be confirmed; addresses are not committed). No alarm on `_oracle_errors`. CPU, memory, and log ERROR/WARN alarms must not use `-conn-`.
- In val and production, `appian-connector-{stage}-jiraNotifier` (reserved concurrency 1, two async retries, then SQS `-jiraNotifier-dlq` with an email alarm) handles `-conn-` ALARM/OK and ECS task-stopped events. It finds the open OY2 ticket with labels `macpro_appian_connector` and `{VAL|PROD}`, `statusCategory != Done`, and an exact summary match, then creates, comments on repeat, or comments on recovery (ticket stays open). Master has `jiraStageLabel: null` and no notifier. Fixed ticket fields live in `src/services/connector/libs/jira-ticket-config.ts`. Secret `appian/{stage}/jira` is JSON with `url` (`https://jiraent.cms.gov`, no trailing slash) and `token` (PEIT Bearer PAT); rotate by hand. Tickets use Epic Link `OY2-29580`, components `BigMAC` and `MACPro Appian`, Working Team Platform Submission, reporter/assignee `PEIT`.
- Existing JDBC source `source.jdbc.appian-connector-dbo-1` publishes to `aws.appian.cmcs.MCP_SPA_PCKG` (`timestamp+incrementing`, 5-minute poll). A second source for MACPro→SMART is staged against view `MCP_SMART_INTEGRATION_VW` → topic `aws.appian.cmcs.MCP_SMART_INTEGRATION_VW` (every change event, no topic compaction, same `dbInfo` and connector read-only login); keep it out of `connector-names.json` / deploy until that login has SELECT. Spec: `docs/macpro-smart-appian-connector-spec.md`. Little data and days without rows are normal; do not add topic or row freshness alarms.
- Tests: `yarn test-tsc`, `yarn test-ci` (vitest, `src/**/*.test.ts`), and `yarn --cwd infra test` (jest, shared fixture `infra/test/fixtures.ts`). `.github/workflows/unit-tests.yml` runs them on pull requests and before every deploy. Yarn workspaces are `src/libs`, `src/services/*`, and `infra`. Unreleased planning specs live under `docs/`; stability work follows `docs/appian-connector-stability-spec.md` and `docs/appian-connector-stability-plan.md`. README docs links point to the GitHub Wiki. Production deploy publishes the alerts stack and the connector stack only. `docs/daily summary/` is git-ignored personal notes.
