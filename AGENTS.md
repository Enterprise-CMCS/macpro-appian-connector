## Learned Workspace Facts

- Connector DB details live in AWS Secrets Manager, not SSM. Master and ephemeral deploys read `appian/default/dbInfo` because `appian/master/dbInfo` does not exist. Val reads `appian/val/dbInfo` and production reads `appian/production/dbInfo`. JSON fields are `ip` (host), `port`, `db` (Oracle SID in the thin JDBC URL), `user` (login), `schema` (table qualifier), and `password`. On master/dev the read-only connector login is `BIGMACREAD`, the schema is `MACPROTEST1`, and the SID is `MACPRO`. The MACPro application login is separate from the connector login. The master/dev Oracle database is in a separate MACPro account, so database networking changes use that account rather than the `bigmac-dev` profile. Leave the val account’s separate `appian/default/dbInfo` unchanged.
- `configureConnectors` reads `legacydbPassword` from its Lambda environment, which is set at deploy, not from Secrets Manager at runtime. It reads connector status once after the config PUT. An auth or lock trace throws and does not restart. It does not poll, and it does not change the dbInfo secret.
- Database username and password changes are manual. The automated credential updater and its CloudFormation stack have been removed. Do not reintroduce an automatic password updater. Full steps are on the Confluence page: https://confluenceent.cms.gov/pages/viewpage.action?pageId=1504366491. Do not copy account IDs, secret values, or EventBridge physical names into this file.
- Lambda names: `appian-connector-production-configureConnectors`, `appian-connector-val-configureConnectors`, `appian-connector-master-configureConnectors`, `appian-connector-production-testConnectors`, `appian-connector-val-testConnectors`, `appian-connector-master-testConnectors`, `appian-connector-val-jiraNotifier`, `appian-connector-production-jiraNotifier`.
- The master stage is the dev environment (stage name `master`). Ephemeral branches deploy into that same environment, and dev means the master stage. A push to `master` auto-opens a release PR to `val`, and a push to `val` auto-opens one to `production`. AWS CLI profiles: `bigmac-dev` (master), `bigmac-val` (val), `bigmac-prod` (production).
- `testConnectors` runs every minute from an EventBridge rule whose state comes from `healthCheckSchedule` in `infra/lib/environment-config.ts`. Master is `ENABLED`. Val and production stay `DISABLED` until Tasks 17 and 18 of `docs/appian-connector-stability-plan.md`; they were disabled because restarts once locked the Oracle user. Stop a scheduled run by disabling that stage's EventBridge rule, not the Lambda, and set `healthCheckSchedule` to match so the next deploy agrees.
- `testConnectors` emits `{connectorName}_failures`, `{connectorName}_task_failures`, `{connectorName}_restart_capped` (every run), `{connectorName}_restarts` (published before a restart; the restart is skipped if that publish fails), and `health_check_heartbeat` (every run, including caught errors) in namespace `appian-connector-{stage}`. It restarts a connector that is not RUNNING, except on Oracle auth or account-lock traces, at most `maxRestartsPerHour` (Lambda env, default 3) times per hour. If it cannot read the restart count, it does not restart. The connector config sets `connection.attempts` to 1. It cannot push new credentials.
- `testConnectors` reads `tasks[].trace`. `ORA-01017`, `ORA-28000`, or `account locked` emits `{connectorName}_oracle_auth_failures` 1 and `{connectorName}_oracle_errors` 1 and does not restart the task. Any other `ORA-` code emits auth 0 and oracle 1 and keeps the existing restart rule. No Oracle trace emits 0 and 0.
- Connection alarms are generated in `infra/lib/connector-alarms.ts` for every name in `src/services/connector/libs/connector-names.json` and named `appian-connector-{stage}-conn-{short}-connector-down`, `-task-down` (Max >= 1, 3 of 5 minutes), `-oracle-auth` (Sum >= 1, 1 of 1), and `-restart-capped`, plus `appian-connector-{stage}-conn-health-check-missing` (only when the schedule is enabled) and `-conn-health-check-errors`. `{short}` is the connector name without `source.jdbc.`. All send alarm and OK notices to `Alerts-appian-alerts-{stage}`. There is no alarm on `{connectorName}_oracle_errors`. CPU, memory, and log ERROR/WARN alarms must not use `-conn-`.
- The connector carries little data, and days without rows are normal. Do not add topic or row freshness alarms.
- Tests: `yarn test-tsc`, `yarn test-ci` (vitest, `src/**/*.test.ts`), and `yarn --cwd infra test` (jest, shared fixture `infra/test/fixtures.ts`). `.github/workflows/unit-tests.yml` runs them on pull requests and before every deploy.
- Email subscriptions on `Alerts-appian-alerts-{stage}` are manual (`aws sns subscribe --protocol email`) and must be confirmed. Addresses are not committed.
- In val and production, `appian-connector-{stage}-jiraNotifier` (reserved concurrency 1, two async retries, then SQS `appian-connector-{stage}-jiraNotifier-dlq` with an email alarm) receives `-conn-` alarm ALARM and OK events from EventBridge and ECS task-stopped events from `ECSFailureEventRule`. It finds the open ticket with `project = OY2 AND labels = macpro_appian_connector AND labels = {VAL|PROD} AND statusCategory != Done` plus an exact summary match. Then it creates the ticket, comments on a repeat, or comments on recovery and leaves the ticket open. Master has `jiraStageLabel: null` and no notifier. Fixed ticket values live in `src/services/connector/libs/jira-ticket-config.ts`.
- The JDBC source `source.jdbc.appian-connector-dbo-1` publishes to Kafka topic `aws.appian.cmcs.MCP_SPA_PCKG` (`timestamp+incrementing`, 5-minute poll). Very little data passes through it, so days without traffic are normal and are not a failure signal.
- Yarn workspaces are `src/libs`, `src/services/*`, and `infra`. README documentation links point to the GitHub Wiki. Unreleased planning specs live under `docs/`. The production deploy workflow publishes the alerts stack and the connector stack only.
- Connector stability and Jira alerting work follows `docs/appian-connector-stability-spec.md` and `docs/appian-connector-stability-plan.md`.
- Secret `appian/{stage}/jira` exists in master, val, and production as JSON with exactly the keys `url` (`https://jiraent.cms.gov`, no trailing slash) and `token` (PEIT's Jira Data Center personal access token, sent as a Bearer token). It uses the default Secrets Manager key. Rotate it by hand with `aws secretsmanager put-secret-value`. No script for it is committed.
- Jira tickets for this repo go to project `OY2` on `jiraent.cms.gov` (not `qmacbis.atlassian.net`). Generated tickets use labels `macpro_appian_connector` plus `VAL` or `PROD`, Epic Link `OY2-29580` (in Done status), components `BigMAC` (id 67202) and `MACPro Appian` (id 78303; an archived `MACPro/Appian` also exists), Working Team Platform Submission (option 51914, required on OY2 Bugs), and reporter and assignee `PEIT`.
- `docs/daily summary/` holds personal notes and is git-ignored.
